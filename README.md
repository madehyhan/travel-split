# Travel Split

奶油粉、白色的中文旅行 AA 记账网页。全部代码在 `index.html` 内，仅使用 HTML、CSS 和 JavaScript；无需安装依赖、登录或后端。

## 预览与使用

1. 将 `index.html` 下载到 MacBook，在 Finder 中右键文件 → 打开方式 → Safari 或 Chrome。
2. 添加所有同行伙伴，然后填写金额、类别、付款人和备注，点击“保存消费”。
3. 右侧显示每人的已付金额、应承担金额和最终转账建议。iPhone 上会自动变成单列。
4. 通过消费记录右侧的“修改”和“删除”调整账单。
5. 记录存放在当前浏览器的 `localStorage`，正常情况下刷新不会消失。建议首次使用后刷新验证。
6. 点击“导出账本备份”下载 JSON；换设备后用“导入备份”恢复。导入会替换当前账本，并有确认提示。
7. 网页底部“下载完整网页”可再次下载单文件版本。

## 分摊规则

- 单一币种：人民币，最多两位小数。
- 整趟旅行的总费用由当前全部参与者均分。新加入或移除伙伴，会重新分摊已有消费。
- 以整数“分”计算。无法均分的几分钱按照伙伴添加顺序分配，例如 1 元分给三人：0.34、0.33、0.33 元。
- 每人余额 = 已付款 − 应承担；正数表示应收，负数表示应付。
- 自动将应付方与应收方配对，生成可全部结清的方案（不承诺数学上最少转账笔数）。
- 转账建议不会发起真实付款；结算转账不要再次记为旅行消费。
- 存在付款记录的伙伴不能直接删除，需先修改这些记录的付款人或删除相关消费。

## 本地保存说明

账本不跨浏览器、设备或网址同步。清除浏览器数据可能删除账本，无痕浏览也可能无法长期保留数据。直接打开本地 HTML 的存储行为由浏览器决定；移动文件、重命名文件或从本地版换到在线版时，请先导出备份。网页会在保存失败时提醒导出备份。

iPhone 推荐用 Safari 打开部署后的网页网址，避免在“文件”App 的预览窗口内运行网页。

## GitHub Pages 免费发布与 iPhone 在线预览

项目仓库：https://github.com/madehyhan/travel-split

源码提交到 `main` 后，可按下面步骤发布：

1. 打开仓库，进入 Settings → Pages。
2. 在 Build and deployment 中，Source 选择 **Deploy from a branch**。
3. Branch 选择 **main**，文件夹选择 **/(root)**，点击 **Save**。
4. 等待几分钟，Pages 页面会显示已发布的网址；也可在 Actions 查看部署进度。
5. 默认网址为 https://madehyhan.github.io/travel-split/ ，实际以 Pages 显示的链接为准。
6. 用 MacBook 或 iPhone 的 Safari 打开网址；可通过 Safari 分享菜单“添加到主屏幕”。

GitHub Free 通常要求使用公开仓库启用 Pages；若 Pages 提示需要升级，可自行选择将仓库设为 Public。公开仓库会公开网页源代码。不要把个人账本 JSON 备份上传到仓库；每位访问者的账本仍保存在各自浏览器中，不会自动上传或同步到 GitHub。

后续修改代码并提交到 `main`，GitHub Pages 会自动重新部署。

## 可执行测试

业务测试使用 Node.js 内置模块，无需 npm 安装依赖：

```sh
cd travel-split
node test.cjs
```

测试覆盖参与者添加、重名、付款记录删除保护、添加/修改/删除消费、保存与重新载入、非法金额、备份数据验证、HTML 转义、保存失败提示，以及 360 组分摊与转账金额守恒场景。`test.cjs` 使用 DOM 和存储模拟，不替代真实浏览器验证。

开发时另外执行了 Chromium 交互测试，检查消费与伙伴管理、备份导入导出、异常输入，以及 390px/1440px 的无横向溢出布局。测试环境不允许访问本地文件/本地服务器，因此采用内存 HTML 页面及模拟 localStorage；尚未在实际 macOS Safari 或 iPhone Safari 上验证原生本地存储。
